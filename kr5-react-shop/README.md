# КР №5 — FishHunter на React

Компонентное SPA-приложение учебного магазина аквариумных рыбок. Это React-вариант контрольной работы №5, продолжающий предметную область КР4. Проект создан на React + Vite и подготовлен к замене локального mock-источника настоящим backend API.

## Возможности

- SPA-навигация без перезагрузки через React Router;
- каталог из 10 товаров, загружаемый асинхронно через API-слой;
- поиск по названию, фильтрация по категории, наличию и диапазону цены;
- сортировка по цене и названию, счётчик результатов и пустое состояние;
- карточка товара и отдельная страница `/catalog/:productId`;
- controlled-форма заявки с проверкой имени, e-mail, телефона, товара и согласия;
- сообщения об ошибках и успехе в интерфейсе без `alert()`;
- черновик формы, корзина и избранное в `localStorage`;
- обработка загрузки, ошибки API и повторная загрузка;
- страница 404 для неизвестного маршрута и обработка отсутствующего товара.

## Маршруты

| URL | Назначение |
| --- | --- |
| `/` | Главная и популярные товары |
| `/catalog` | Каталог, поиск, фильтры и сортировка |
| `/catalog/:productId` | Страница товара по параметру маршрута |
| `/order` | Форма заявки |
| `/cart` | Корзина |
| `*` | Страница 404 |

## Подготовка к backend API

Компоненты не знают, откуда берутся товары: каталог и страница товара обращаются только к `src/api/productsApi.js`. Сейчас `requestJson` получает данные из `/products.json`, но для подключения сервера достаточно заменить `PRODUCTS_URL` на endpoint, сохранив функции `getProducts` и `getProductById`. `AbortController`, состояния `isLoading` и `error`, а также повторная загрузка уже предусмотрены.

## Что показать на защите

Запустить `npm run dev`, открыть `/catalog`, показать поиск «неон», категорию и сортировку, перейти в `/catalog/1`, открыть `/order` и отправить пустую форму, затем проверить `/catalog/999` и `/unknown-page`. После этого показать `src`, `products.json`, API-слой и этот README.
