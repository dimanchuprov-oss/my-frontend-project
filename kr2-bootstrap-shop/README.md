# FishHunter — контрольная работа №2

Многостраничный учебный магазин аквариумных рыбок и оборудования. Проект выполнен на Bootstrap 5.3.8 с локальным подключением ресурсов, без CDN.

> Цены, наличие, доставка и заявки демонстрационные. Форма проверяет данные только в браузере: ничего не отправляется и не сохраняется.

## Bootstrap и интерфейс

- Bootstrap 5.3.8 подключён из `vendor/bootstrap/`; внешний CDN и сборка не требуются.
- Сетка Bootstrap `container` / `row` / `col-*` используется на страницах каталога, товара и заявки, а также в адаптивной навигации и подвале.
- Используются компоненты Bootstrap: navbar и dropdown, accordion, carousel, tabs, toast, pagination, modal, cards, breadcrumbs, badges и form controls.
- `css/custom.css` задаёт общую цветовую палитру, типографику, отступы, варианты карточек, состояния фокуса и мобильные правила поверх Bootstrap.
- В каталоге представлены три категории товаров и несколько видов карточек; поиск, фильтры, сортировка, избранное и пагинация работают на клиенте.
- В каталоге можно открыть быстрый просмотр товара. На странице товара доступны вкладки описания, характеристик и получения.
- Заявка считает стоимость с учётом доставки, проверяет контактные данные и показывает предварительный итог перед демонстрационным подтверждением.
- Выбранные товары для избранного сохраняются в `localStorage`, если браузер разрешает такое хранилище.

## Запуск и проверка

Проект статический, зависимости устанавливать не нужно. Откройте `index.html` в браузере или запустите локальный сервер из каталога проекта:

```sh
python3 -m http.server 8000
```

Затем перейдите на <http://localhost:8000>.

Проверка структуры, локальных ссылок и обязательных Bootstrap-подключений:

```sh
python3 scripts/check_project.py
```

Также можно проверить синтаксис JavaScript:

```sh
node --check js/main.js
node --check js/products.js
```

Для ручной проверки пройдите основные сценарии:

1. Откройте каталог, примените категорию и поиск, переключите вид карточек и страницу.
2. Откройте товар, смените вкладку и передайте товар и количество в форму заявки.
3. В заявке проверьте самовывоз и доставку, обязательность адреса, ошибки формы и предварительный итог.
4. Убедитесь, что заявка не отправляет введённые данные.

## Публикация на GitHub Pages

Проект публикуется из подпапки `kr2-bootstrap-shop/` текущего репозитория `dimanchuprov-oss/my-frontend-project`. Workflow [`.github/workflows/deploy-kr2-pages.yml`](../.github/workflows/deploy-kr2-pages.yml) загружает на GitHub Pages только содержимое этой папки; старый сайт из корня репозитория в артефакт публикации не попадает.

В настройках репозитория выберите **Settings → Pages → Build and deployment → Source → GitHub Actions**. Не выбирайте ветку `main` и `/(root)`: они опубликуют старый сайт из корня репозитория.

После успешного запуска workflow:

- Репозиторий: <https://github.com/dimanchuprov-oss/my-frontend-project>
- GitHub Pages: <https://dimanchuprov-oss.github.io/my-frontend-project/>

Первую публикацию можно запустить вручную во вкладке **Actions → Deploy KR2 to GitHub Pages → Run workflow**. Дождитесь зелёного статуса задачи `deploy`; затем откройте ссылку Pages выше. Новые изменения в этой папке будут публиковаться автоматически после push в `main` или `feature/css-architecture-states`.
