# FishHunter — контрольная работа №3

Проект по дисциплине «Фронтенд и бэкенд разработка».
Тема: «Адаптивная вёрстка и доступность многостраничного HTML/CSS-сайта».

Многостраничный магазин аквариумных рыбок адаптирован для телефонов, планшетов и настольных экранов без Bootstrap. За основу взят HTML/CSS-проект контрольной работы №1; папка `kr2-bootstrap-shop/` не используется.

## Ссылки и просмотр

- Репозиторий: https://github.com/dimanchuprov-oss/my-frontend-project
- GitHub Pages: https://dimanchuprov-oss.github.io/my-frontend-project/ (публикация ещё не проверена).

## Адаптивные решения

- `responsive.css` подключён после основного файла стилей на всех пяти страницах.
- На телефонах и небольших планшетах навигация свёрнута в доступное меню-кнопку с компактной сеткой ссылок; на широком экране с 901 px ссылки располагаются в одну строку. Кнопка сообщает состояние через `aria-expanded`, а меню закрывается после выбора ссылки и клавишей Escape.
- Используются `min-width`-медиазапросы: одноколоночная мобильная раскладка расширяется от 640, 768 и 1024 px.
- Размеры основного текста и заголовков плавно адаптируются через `clamp()`; типографика меню, подписей таблиц, подсказок и подвала тоже масштабируется.
- Карточки, каталог с фильтром, карточки товаров, формы и диалог подстраиваются под ширину экрана.
- `srcset` и `sizes` дают браузеру выбор уменьшенных вариантов фотографий; CSS ограничивает ширину изображений контейнером.
- Таблицы прокручиваются внутри отдельных подписанных областей, не создавая горизонтальную прокрутку всей страницы.
- Размеры полей и кнопок подходят для нажатия на сенсорном экране; модальное окно ограничено размерами viewport.
- Ссылка «Наверх» не перекрывает элементы интерфейса на узких экранах.
- Контрольные ширины для ручной проверки: 360, 430, 768, 1024 и 1440 px.

## Доступность

- На всех страницах есть ссылка пропуска к основному содержимому и единственный целевой `<main>`.
- Сохранены семантическая структура, подписи полей, осмысленные `alt`, активная страница навигации и видимый клавиатурный фокус.
- Учитываются `prefers-reduced-motion` и клавиатурная прокрутка таблиц.
- Заказ оформляется через нативный `<dialog>`; сообщения формы объявляются через `role="alert"` и `role="status"`.
- Форма заказа и форма обратной связи демонстрационные: валидация происходит в браузере, данные не отправляются и не сохраняются.

## Проверка и Lighthouse

Локальные проверки:

```sh
python3 scripts/check_project.py
node --check js/main.js
git diff --check
```

Дополнительно проверьте клавиатурную навигацию, отправку пустых и заполненных форм, модальное окно, горизонтальную прокрутку и ширины, перечисленные выше.

Lighthouse CLI 13.5.0: категория Accessibility получила 100/100 на `index.html`, `catalog.html` и `order.html`. HTML-отчёты сохранены в `lighthouse/`. Автоматический Lighthouse-аудит проверяет только часть доступности, поэтому дополнительно пройдите интерфейс клавиатурой и проверьте формы вручную.

## Технологии

HTML5, CSS3 и JavaScript без фреймворков и сторонних библиотек. В каталоге показаны учебные статические фильтры; кнопка применения отключена. Контактные данные вымышленные.
