# FishHunter — контрольная работа №4

Интерактивная версия многостраничного учебного магазина аквариумных рыбок. КР4 продолжает адаптивный сайт КР3: HTML/CSS-страницы, навигация, формы, изображения и responsive-стили сохранены, а каталог и заявка получили поведение на JavaScript.

## Репозиторий и запуск

- Ссылка на папку проекта для сдачи после публикации текущей ветки: [kr4-js-shop на GitHub](https://github.com/dimanchuprov-oss/my-frontend-project/tree/feature/css-architecture-states/kr4-js-shop).
- Исходная площадка проекта: [dimanchuprov-oss/my-frontend-project](https://github.com/dimanchuprov-oss/my-frontend-project), каталог `kr4-js-shop/`.
- Папка подготовлена как самостоятельная основа репозитория `kr4-js-shop`. Для отдельной сдаваемой ссылки её нужно опубликовать в одноимённом репозитории; существующий remote текущего рабочего проекта указывает на репозиторий КР3.
- Запуск без сборки: откройте `index.html` или запустите в этой папке `python3 -m http.server 8000`, затем перейдите на <http://localhost:8000>.
- Проверка проекта: `python3 scripts/check_project.py`; синтаксис: `node --check js/data.js`, `node --check js/catalog.js`, `node --check js/validation.js`, `node --check js/main.js`.

## Каталог

`js/data.js` содержит массив из 10 объектов в одинаковом формате: `id`, `title`, `category`, `price`, скидка, рейтинг, наличие, изображение и описание. Идентификаторы уникальны, цены — числа. Категории каталога формируются из этих данных, а адаптивные варианты фотографий назначаются карточкам через `srcset` и `sizes`.

На странице каталога работают:

- поиск по части названия без учёта регистра;
- категория, диапазон цены, наличие и избранное;
- сортировка по возрастанию/убыванию цены и по названию;
- число найденных товаров, средняя цена и пустое состояние;
- выбор товара для заявки из ссылки карточки.

`js/catalog.js` строит карточки через `document.createElement()`, задаёт классы через `classList`, добавляет элементы через `append()` и выводит текст через `textContent`. Динамические строки данных не попадают в `innerHTML`. `textContent` создаёт текстовый узел, поэтому строка вроде `<img onerror=...>` будет показана как текст, а не разобрана браузером как HTML-разметка. Адрес изображения берётся из локального массива проекта.

## Формы и сообщения

Заявка проверяет обязательные поля, формат e-mail и телефона средствами HTML constraint validation и `checkValidity()`. Ошибка и результат проверки отображаются в блоках `role="alert"` / `role="status"` на странице; `alert()` не используется. Это демонстрационные формы: запросы и персональные данные на сервер не отправляются.

## Самостоятельные доработки

- Каталог расширен до 10 товаров с рейтингами, скидками, описаниями и наличием.
- Добавлены фильтр по цене, фильтр наличия и сортировка по названию.
- Избранное сохраняется в `localStorage`; ошибки чтения или записи сообщаются на странице и в консоли.
- Добавлены сводка с количеством и средней ценой, пустое состояние и предзаполнение товара в форме по ссылке из каталога.
- Стили карточек и контролов сохраняют адаптивные сетки и клавиатурный фокус основы КР3.

## Проверочные сценарии

1. Открыть каталог, ввести `неон`, выбрать категорию и сортировку; список должен обновляться при каждом изменении.
2. Установить минимальную/максимальную цену и «Только в наличии», затем сбросить фильтры.
3. Добавить товар в избранное, включить фильтр «Только избранное» и перезагрузить страницу.
4. Задать запрос без совпадений и проверить пустое состояние и счётчик.
5. Перейти из доступной карточки к заявке: товар должен быть выбран автоматически.
6. Отправить пустую форму, затем корректно заполненную; сообщения появляются в форме, без `alert()`.
7. Проверить консоль и адаптивность на ширине 360, 768 и 1024 px.
