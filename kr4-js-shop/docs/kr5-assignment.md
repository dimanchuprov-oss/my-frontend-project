# Постановка контрольной работы №5

**Тема:** компонентная frontend-разработка на React или Vue с подготовкой проекта к подключению backend API.

## Цель

Перенести предметную область магазина FishHunter из HTML/CSS/JavaScript-проекта КР4 в компонентную frontend-архитектуру и подготовить слой данных к последующей замене mock-источника на backend API.

Рекомендуемый стек — **React + Vite**. Допускается **Vue + Vite**, если студент самостоятельно реализует и может объяснить структуру проекта.

## Обязательные требования

- Создать проект через Vite.
- Разбить интерфейс на компоненты: шапка, карточка товара, список товаров, каталог/фильтры и форма заявки.
- Загружать товары из mock-массива или `products.json`.
- Реализовать каталог с поиском по названию, категорией и сортировкой.
- Использовать состояние и декларативные обработчики событий выбранного фреймворка.
- Добавить несколько страниц с маршрутизацией: главная, каталог, товар и заявка/корзина.
- Создать API-модуль `productsApi.js`, отделив получение данных от компонентов и подготовив его к будущему HTTP API.
- Подготовить форму заявки с базовой валидацией.
- Описать запуск, структуру компонентов и источник данных в `README.md`.

## Рекомендуемая структура React-проекта

```text
kr5-react-shop/
├── public/
│   └── products.json
├── src/
│   ├── api/productsApi.js
│   ├── components/
│   │   ├── Header.jsx
│   │   ├── ProductCard.jsx
│   │   ├── ProductList.jsx
│   │   ├── CatalogControls.jsx
│   │   └── OrderForm.jsx
│   ├── pages/
│   │   ├── HomePage.jsx
│   │   ├── CatalogPage.jsx
│   │   ├── ProductPage.jsx
│   │   ├── CartPage.jsx
│   │   └── NotFoundPage.jsx
│   ├── hooks/useLocalStorage.js
│   ├── App.jsx
│   ├── main.jsx
│   └── index.css
├── README.md
└── package.json
```

Для Vue структура аналогична: `.vue`-компоненты, `App.vue`, `main.js`, а для переиспользуемой логики допустимы composables.

## Что показать на защите

- Как данные передаются в компонент карточки и список.
- Как состояние обновляется при поиске и выборе категории.
- Как устроена маршрутизация и API-слой.
- Чем компонентный подход отличается от ручного изменения DOM в КР4.
- Как заменить mock-данные реальным backend API без переписывания компонентов.
